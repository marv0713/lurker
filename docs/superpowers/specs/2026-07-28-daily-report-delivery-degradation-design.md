# 日报推送降级与故障可见性设计

**日期：** 2026-07-28
**状态：** 已确认

## 1. 目标

日报接收人必须能够区分：

1. 日报正常生成且存在可操作候选；
2. 日报正常生成但市场处于防守、观察或没有候选；
3. 日报主体可用，但市场温度 rollout 尚未验收或辅助数据降级；
4. 日报任务真正失败。

“没有机会”和“辅助能力未验收”都不得表现为静默不推送。

## 2. 交付状态

日报任务对外使用三个状态：

| 状态 | 含义 | 通知行为 | 退出状态 |
|---|---|---|---|
| `SUCCESS` | 主体数据有效，所有启用能力可用 | 推送正常日报 | 成功 |
| `DEGRADED` | 主体数据有效，但辅助能力未验收或非关键数据降级 | 推送带降级标识的日报 | 成功 |
| `FAILED` | 行情为空、关键资金数据无效、报告构建异常或落盘异常 | 不推正常日报；发送独立故障通知 | 非零 |

市场处于进攻、观察、防守以及候选数量为零均是策略结论，不改变交付状态。

## 3. Rollout 门禁语义

`professional_flow_daily` 的市场温度 rollout 检查从“整份日报推送门禁”改为
“温度驱动操作建议门禁”。

当 rollout artifact 缺失、未审批、指纹不一致、回放不足或状态集中度超标时：

- 任务状态为 `DEGRADED`；
- 日报仍然推送；
- 推送标题增加 `[降级]`；
- 日报顶部披露具体门禁原因；
- 市场、ETF、板块、个股资金等事实数据继续展示；
- 市场温度可以展示为观测值，但必须标记“未完成上线验收”；
- 禁止生成或升级任何依赖市场温度的 `2%候选`；
- 弹簧观察、退潮提醒等非操作性栏目可以继续展示。

不得通过伪造或自动批准 rollout artifact 恢复完整能力。

## 4. 数据质量与故障通知

现有关键数据校验继续生效：

- 行情快照为空属于 `FAILED`；
- 请求资金日报但市场、板块和个股资金全部为空属于 `FAILED`；
- 关键资金源失败属于 `FAILED`；
- `stock_flows`、`margin`、`core_etfs` 单独失败属于 `DEGRADED`。

`FAILED` 时使用日报接收渠道发送独立通知：

- 标题：`[故障] 职业资金雷达日报 YYYY-MM-DD`；
- 正文包含失败阶段、简化后的异常类型和原因、报告日期；
- 不附带伪造的策略结论；
- 通知发送失败不能吞掉原始异常，CLI 仍以非零状态退出。

不使用 watchlist 异常体检的接收人配置。

## 5. 运行流程

1. 在策略运行前解析启用策略并检查 rollout 状态。
2. 把 `temperature_rollout_approved` 传入职业资金策略。
3. 职业资金策略在未批准时强制清空 `2%候选`，并返回降级元数据。
4. 渲染报告并追加统一降级说明。
5. 完成数据库和文件落盘。
6. 根据主体数据质量得出 `SUCCESS`、`DEGRADED` 或 `FAILED`。
7. `SUCCESS` 和 `DEGRADED` 推送日报；`FAILED` 推送故障通知并返回非零。

## 6. 可观测性

CLI 最终输出必须包含单行状态：

```text
DAILY_JOB_STATUS=SUCCESS
DAILY_JOB_STATUS=DEGRADED reason="..."
DAILY_JOB_STATUS=FAILED stage="..." reason="..."
```

cron 继续保留完整日志。后续排查时不需要根据“有没有收到日报”猜测任务状态。

## 7. 验收标准

必须由自动化测试证明：

1. rollout 缺失时仍调用日报 notifier；
2. 降级日报标题含 `[降级]`，正文包含门禁原因；
3. rollout 未批准时，即使原始条件满足也不产生 `2%候选`；
4. 市场防守或没有候选时仍推送正常或降级日报；
5. 关键数据失败时不推正常日报，而推送 `[故障]` 通知；
6. 故障通知失败时原始异常仍传播；
7. `--no-push` 时正常、降级和故障通知均不发送；
8. CLI 输出包含准确的 `DAILY_JOB_STATUS`；
9. watchlist 专属通知配置不受影响；
10. 全量测试与 Ruff 检查通过。

## 8. 非目标

- 本次不自动批准 rollout artifact；
- 本次不解决两融接口权限和历史市场资金源缺失；
- 本次不改变市场温度真值表；
- 本次不改变 watchlist anomaly、周报和月报的推送规则。
